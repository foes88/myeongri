# 상담 이력과 개인정보 보관 정책 (초안 — 법률 검토 전)

> 이 문서는 개발 설계이며 법률 자문이 아니다. 개인정보 처리방침·이용약관·환불정책은 시행 전에 개인정보보호법·전자상거래법 전문가 검토가 필요하다(게이트 G6, G10).

## 수집 항목 (최소화)
| 항목 | 필수 | 목적 | 보관 |
|---|---|---|---|
| 이메일(로그인) | ○ | 계정·결제 안내 | 회원 유지 중 + 탈퇴 후 법정 보관분만 |
| 생년월일시·성별·출생지 | ○ (분석 시) | 명식 계산 | 암호화 저장, 사용자가 "저장 안 함" 선택 시 분석 직후 폐기 옵션 |
| 이름 | ✕ | 받지 않음 | — |
| 현실 상황(직업 등) | 선택 | 상담 맞춤 조언 | 상담 이력과 함께, 사용자가 개별 삭제 가능 |
| 결제 정보 | PG 위탁 | 결제 | 카드번호 등은 **자사 서버 저장 금지**(PG 토큰만) |

## 보관·삭제
- 기본: 출생정보 저장 OFF(일회성 분석). 저장 ON 시에만 profile 생성.
- 구매한 보고서 재열람을 위해 `analysis_report`(구조 JSON + 설명)는 저장하되 출생정보 원문은 보고서에 포함하지 않고 `chart_snapshot` 참조 + 가림 처리(연월일 표시 옵션).
- 회원 탈퇴: 즉시 접근 차단 → 30일 유예 후 profile/consult/report 하드 삭제. 법정 보관 대상(결제·분쟁 기록)은 개인 식별 최소화 후 기간 만료 시 삭제.
- 사용자 요청 삭제(개별 상담/명식): 24시간 내 소프트 삭제, 7일 내 하드 삭제, 백업은 최대 35일 롤링 후 소멸.
- 공유 링크: 기본 가림, 서버 측 랜덤 토큰, 만료·회수, 검색엔진 색인 차단.

## 암호화·접근
- 전송 TLS1.2+, 저장 AES-256 envelope 암호화(KMS 키, 필드 단위: birth_enc, consult text).
- 상담 기록 접근: 소유 user 만. 운영자 접근은 `support_access_grant`(사용자 동의 + 기간 + 감사 로그) 있을 때만.
- 내부 분석·BI 이벤트에는 profile/출생정보/상담 원문 미포함. 해시된 익명 id 와 집계 지표만.

## 로그 비식별화
- 요청 본문 로깅 금지. 구조 로그는 `report_id`, `chart_snapshot_id`, 상태, 소요시간만.
- LLM 호출 프롬프트에는 출생 원문 대신 구조 JSON(간지·claim_id)만 전달. 외부 LLM 사업자에 출생정보 원문을 보내지 않는다.
- 저장소: 공개/비공개 구분 없이 실제 출생정보 커밋 금지. `app.privacy_scan` + 골든 케이스 구조 검증을 CI 필수 단계로 한다(이미 구현).

## 사용자 권리
열람·정정·삭제·처리정지·이동(JSON 내보내기). 동의 철회 시 해당 목적 처리 중단.

## 미성년자·민감 주제
- 14세 미만 가입 불가(법정대리인 동의 흐름은 별도 검토).
- 건강·사망·자해 관련 질문은 해석을 제공하지 않고 전문 기관 안내로 전환.
