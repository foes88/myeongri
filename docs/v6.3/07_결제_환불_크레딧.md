# 결제·환불·크레딧 상태 설계 (미구현 — 승인 전 보류)

실제 PG 연동·과금은 하지 않는다. 구현 시 순서: **모의 PG → 통합 테스트 → PG 샌드박스 → 승인 후 실결제**.

## 주문·결제 상태기계
```
order: CREATED → PENDING_PAYMENT → PAID → FULFILLING → COMPLETED
                      ↘ EXPIRED / CANCELED            ↘ FAILED_REFUNDING → REFUNDED
payment: INITIATED → AUTHORIZED → CAPTURED → (PARTIALLY_)REFUNDED | FAILED | CHARGEBACK
```
- 상태 전이는 서버만, 허용 전이표 외 전이는 예외. 모든 전이는 `audit_log`.
- 웹훅은 **서명 검증 + 타임스탬프 허용치 + 이벤트 id 멱등 저장**(`webhook_event.event_id UNIQUE`) 후 처리. 검증 실패는 200 으로 삼키지 않고 거부·경보.
- 결제 확정은 웹훅/서버 조회로만. 클라이언트 리다이렉트 성공 표시를 신뢰하지 않는다.

## 중복 방지
- 주문 생성 `Idempotency-Key`(user+key UNIQUE). 동일 키 재요청은 기존 주문 반환.
- 크레딧 차감은 `credit_ledger` 에 `(report_id, reason='consume')` UNIQUE → 재시도해도 1회만 차감.
- 분석 요청: 차감 → 생성 → 성공 시 확정, 실패 시 `reason='restore'` 행으로 복원(트랜잭션 + 아웃박스).

## 크레딧
- 원장(ledger) 방식: 잔액 = Σ(+충전, −차감, +복원, −만료, −환불회수). 잔액 컬럼은 캐시일 뿐 진실은 원장.
- 종류: 유료 크레딧(만료 있음), 무료 체험 크레딧(한도·소멸 별도).
- 만료 잡은 사전 고지(만료 N일 전)와 만료 로그를 남긴다. 법정 최소 유효기간·표시 의무는 법률 검토 항목.

## 환불·취소 정책 설계안 (법률 검토 전)
| 상황 | 처리 |
|---|---|
| 결제 후 미사용 | 전액 환불(청약철회 가능 기간 내) |
| 분석 실패/서비스 오류 | 자동 복원 또는 환불 |
| 보고서 열람 후 | 디지털 콘텐츠 제공 개시 동의·고지 후에는 제한 가능(법률 검토 필수), 단 **계산 오류·정정 사유는 무상 재발행/환불** |
| 중복 결제 | 자동 감지·즉시 환불 |
| 이용권 만료 | 만료 전 환불 요청 가능 범위는 약관 확정 후 |
- 환불 시 크레딧 회수가 음수가 되면 계정 정지 대신 미수 처리 후 안내.
- 환불 사유 코드화(분석 불만/오류/중복/단순 변심/기타) → 운영 지표.

## 테스트 계획(모의 PG)
중복 웹훅, 순서 뒤바뀐 웹훅, 서명 위조, 타임아웃 후 재시도, 부분 환불, 분석 실패 복원, 동시 요청 이중 차감, 만료 경계, 무료 한도 경합 — 전부 자동화 후에만 PG 샌드박스로 진행.

## 보안
PG 시크릿은 서버 환경변수만, 카드 정보 비저장, 웹훅 엔드포인트 IP/서명 제한, rate limit, 결제 관련 로그에 PII 없음.
