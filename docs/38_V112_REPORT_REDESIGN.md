# v11.2 결과 화면 정보 구조 재구성

> 표시·정보 구조 개선만 했다. 계산·판정·해석 문장은 바꾸지 않았다(백엔드 코드 변경 없음). 브랜치 `feature/v11-report-redesign`.
> 자동 테스트 통과와 실제 사용성은 다르다: **이해도 개선은 미평가**(사람 평가 0건).

## 1. 변경 전후 정보 구조
| 전 (v11.1) | 후 (v11.2) |
|---|---|
| 컨트롤 바 → 사주 결론(특징·변화·관점 3칸) → 내 사주의 모습(오행·계절·성향) → 시기별 흐름(타임라인·표·**긴 연도 풀이**·월별) → 분야별 해석 → 한계 → 질문·저장 | 컨트롤 바 → **① 올해의 핵심 해석**(한 문장 + 보조 1~2문장 + ‘자세한 해석 보기’) → **② 올해의 주요 변화**(2~3개 + 기존 판정 요약) → **③ 분야별 해석**(탭, 핵심 + 첫 문단, ‘상세 해석 펼치기’) → **④ 시기별 흐름**(타임라인·표·월별) → **⑤ 해석의 근거**(기본 접힘: 사주 구조·오행·계절·한계) → 계산 상태·네 기둥 → **⑥ 질문·저장** |

## 2. 각 영역의 역할 (같은 문장을 반복하지 않도록)
- ① 핵심 해석: 선택한 해의 종합 머리 문장(기존 `overall.headline`)의 첫 문장을 가장 큰 글자로, 나머지 문장을 보조로. 연도를 바꾸면 따라 바뀐다. 장식(배경·인장·붓 밑줄)은 걷어 냈다. 상세(해 패널: 자세한 풀이·반대 근거와 한계·현실 관점)는 ‘자세한 해석 보기’ 안에 원문 그대로.
- ② 주요 변화: 기존 데이터의 문장만 사용 — 이 해에 달라지는 점(또는 이 해의 주제), 변화가 적용되는 기간(입춘·큰 흐름 교체 구간), 점검할 점/반대로 보는 근거. 각각 첫 문장을 보이고 나머지는 ‘자세히 보기’. 아래에 기존 판정(기회·주의·양면·안정·근거 부족·변화 없음)을 기호+글자로 묶어 요약(새 판단 없음).
- ③ 분야별 해석: 분야 탭 순서·이름은 그대로. 종합운 탭은 핵심 해석·주요 변화·해 패널에 이미 있는 문장을 다시 쓰지 않는다(지운 문장은 모두 위에 있어야 한다는 테스트).
- ⑤ 해석의 근거: 사주 구조 요약(특징·변화·관점·왜 그렇게 읽나요·조건), 내 사주의 모습(자연 비유·오행 막대(기본)·순환도(접힘 보조)·계절 균형·성향), 해석의 한계. 판정 근거는 숨기지 않고 첫 화면의 핵심 해석을 방해하지 않게 접어 둔다.
- 해 패널의 ‘분야별로 읽으면’ 목록은 분야 탭과 중복이라 제거했다.

## 3. 시각 지침 반영
핵심 해석 26px 이상(화면에서 가장 큰 글자), 보조 18px, 본문 17px·행간 1.8, 섹션 제목 24~30px. 카드·테두리는 줄이고 구획은 가는 선과 여백으로. 펼치기는 모두 같은 ▸/▾ 표시(키보드 Enter 로 열림, 네이티브 details/summary). 주 버튼(자세한 해석 보기)과 보조 버튼 구분. 색만으로 구분하지 않고 기호+글자를 병기.

## 4. 질문·저장
- 질문: 목적 한 줄(‘지금 보고 있는 연도·월·분야를 기준으로 답합니다. 질문에 연도나 월을 적으면 그쪽이 우선합니다.’)과 예시를 넣었다. 기존 규칙 기반 QA·맥락 연동은 그대로.
- 저장: ‘저장하려면 로그인이 필요합니다’를 먼저 알린다. 인증·저장·삭제·내보내기 정책은 그대로.

## 5. 검증
- 브라우저 119개 통과(신규 `test_v112_report.py` 7개: 선택한 해·분야의 **원문 문장이 모두 화면에 있음**, 화면 판정 라벨 = API 판정, 첫 화면 핵심 해석·읽기 순서, 키보드로 펼침, 로그인 안내·질문 목적).
- 옛 구성(좌우 2열 시기별 풀이·인장·분야 목록)을 전제한 기존 테스트는 새 구성에 맞게 고쳤다.
- 페이지 길이(5년·월별 열림): 1440px 5645→3914px, 360px 10851→6715px. 캡처는 저장소 밖 `backend/data_private/ux/v112/`.
