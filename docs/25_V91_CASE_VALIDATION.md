# v9.1 실제 사례 기반 통변 검증 — 구조와 사용법

> 상태: **도구와 합성 테스트까지 구현.** 실제 사례 0건이므로 실제 사례 검증은 **미검증**이다. 합성 테스트 통과는 도구가 의도대로 동작한다는 뜻일 뿐 해석 품질의 증거가 아니다.

## 데이터 구조 (backend/data_private/cases/, 암호화·gitignored)
| 파일 | 내용 |
|---|---|
| cases.enc | 사례 ID(익명), 양/음력·윤달, 출생 연월일시, 출생지, 성별, 출생 시각 신뢰도(A 출생 기록·증빙 / B 가족 기록 / C 추정 / D 모름), 사용 동의와 범위(dev/validation/both), 분할 결과 |
| events.enc | 사건 연도·월, 분야(career, job_change, wealth, love_marriage, family, real_estate, overall), 종류, 출처 설명, 출처 신뢰도(high/medium/low) |
| frozen.enc | 사건을 보지 않고 만든 연도×분야 예측(톤·점수·문장)과 해시, 규칙 버전 |
| evallog.enc | 검증 사례를 평가한 기록(규칙 버전 포함) — 오염 감지용 |

동의가 없으면 저장되지 않고, `remove` 로 사례·사건·예측이 모두 지워진다. 보고서·CLI 출력에는 출생 정보와 사례 ID가 없다.

## 사후 맞춤 방지 장치
1. **분리:** 입력 시 한 번 개발(dev)/검증(validation)으로 나뉘고 바뀌지 않는다(`scope=both` 는 해시로 약 30%가 검증).
2. **사건 비참조 생성:** 예측 생성은 `CaseInput`(출생 정보)만 받는다. 사건 파일은 생성 단계에서 열리지 않는다(테스트로 확인).
3. **고정 구간:** 분석 연도는 만 18~70세(상한은 봉인 시점 연도). 사건이 없는 해도 모두 비교 대상.
4. **봉인:** 예측은 해시로 봉인되고, 봉인 전에는 사건을 열 수 없다. 다시 봉인하면 `refrozen` 으로 표시된다.
5. **규칙 수정 금지의 흔적:** 검증 사례를 평가한 뒤 규칙 버전이 바뀌면 `validation_contaminated` 가 켜진다. 그 검증은 더 이상 독립적이지 않으므로 새 검증 사례가 필요하다.
6. **시주 후보가 여럿인 명식:** 사전 등록 규칙대로 입력한 시계 시각 기준의 주 후보를 자동 사용하고, 모호했다는 사실을 기록한다.

## 사전 등록된 판정 기준 (결과를 본 뒤 바꾸지 않는다)
- 방향성 주장(strong) = 톤이 기회/주의. 양쪽을 다 말하는 `mixed` 는 모호한 주장(weak)이며 `any` 수준에서만 센다.
- 사건 해 = 같은 연도·같은 분야에 출처 high/medium 사건이 있는 해. 1~2월 사건은 입춘 귀속이 모호해 제외(별도 집계). 사후에 의미를 연결하는 해석은 적중으로 세지 않는다.
- 1차 분석은 출생 시각 신뢰도 A·B 사례만. C·D 는 따로 집계.
- 지표: 탐지율, 오탐률(사건 없는 해), 정밀도, 기준율 대비 배수, 같은 사례 안에서 주장 해를 섞는 순열 검정(p), 연도별·분야별 구별 가능성, 명식 간 고유성, 재생성·분석 범위 일관성, 불확실성 표현(반대 근거·한계 포함률, 단정 표현 수).
- 분야별 사건 해가 30개 미만이면 **결론을 내지 않는다**("표본 부족"). 일반 인구 통계는 `--baseline` 파일(분야별 연간 사건 비율)을 주면 비교하고, 없으면 "미제공".
- 판정 문구: 미평가 / 표본 부족 / 예비 단서(재현 필요) / 구별 능력 미확인. **예측 정확도라고 부르지 않는다.** "구별 능력 미확인"은 실패가 아니라 결과이며, 그 경우 사건 예측이 아니라 전통 해석을 통한 자기 이해·상담 용도로 위치를 정하는 것이 타당하다.

## 사용
```
cd backend
python -m tools.case_eval template          # CSV 양식
python -m tools.case_eval import 내파일.csv
python -m tools.case_eval status
python -m tools.case_eval freeze --all      # 사건을 읽지 않고 예측 봉인
python -m tools.case_eval report --out report.json
python -m tools.case_eval remove 사례ID      # 동의 철회
python -m tools.classical_audit --write ../docs/24_V91_CLASSICAL_AUDIT.md
```
실제 사례를 넣을 때는 동의 범위를 확인하고, 사건 출처(어떻게 알게 된 사건인지)를 반드시 적는다. 이름·연락처는 넣지 않는다(사례 ID는 익명).

## 합성 명식 30개 구조 측정 (2026-11-02, 사건 없음)
무작위 합성 명식 30개(만 18세~2026년), 분야 7개×연도별 예측 4,473블록. **예측 정확도가 아니라 엔진의 구조적 특성**이며 실제 사례 검증이 아니다.

| 지표 | 결과 | 읽는 법 |
|---|---|---|
| 방향성 또는 모호한 주장 비율 | 89.2% | 거의 모든 (연도, 분야)에서 무언가를 주장함 → 사건 탐지의 선택성이 낮을 수밖에 없다(연간 사건 비율은 보통 이보다 훨씬 낮음) |
| 모호한 주장(mixed) 비율 | 주장 중 36.9% | 양쪽을 다 말해 반증하기 어려운 문장 |
| 연도별 구별 가능성(중앙값) | 0.29 | 한 사람의 연도 간 톤이 얼마나 다른가(0=전부 같음). (명식, 분야) 쌍의 53%가 0.3 미만 |
| 분야별 구별 가능성(중앙값) | 0.43 | 같은 해에 분야 간 톤이 다른 정도 |
| 명식 간 고유성(1=전부 다름) | 재물 0.66, 직업 0.62, 종합 0.58, 연애 0.54, 이직 0.50, 부동산 0.50, **가족 0.12** | 가족·인간관계운은 사실상 명식과 무관하게 같은 톤 |
| 단정 표현 | 0건 | 불확실성 표현: 한계 안내 100%, 반대 근거 포함 75% |
| 시주 후보가 여럿(주 후보 자동 사용) | 30개 중 8개 | 출생 시각이 경계에 걸린 명식 비율 |

### 확인된 문제 (이번에는 수정하지 않음)
1. **가족·인간관계운은 94%가 ‘주의’ 톤**이다. 연도·명식에 따라 거의 변하지 않아 해석이 구별력을 갖지 못한다(구조상 궁위 관계 위주로 판정되는 것으로 보임 — 원인 분석 필요).
2. **이직·취업운은 ‘기회’ 톤이 한 번도 나오지 않는다**(혼합 50%, 주의 40%). 톤 판정 규칙이 한쪽으로 치우쳐 있을 가능성.
3. **전체적으로 주장 비율이 너무 높다**(89%). 변화가 없는 해는 "주장 없음"으로 분명히 말해야 사건 해와 구별된다. 지금은 구별력이 낮아 사건과 비교해도 의미 있는 결과가 나오기 어렵다.
4. 직업운 헤드라인 문장의 고유 비율이 51%로, 절반이 다른 해·다른 사람과 같은 문장이다.

수정은 실제 사례 평가 계획(개발/검증 분리)을 세운 뒤에, 개발 사례로만 효과를 보고 검증 사례는 봉인한 채로 한다.

## v9.5 보강 — 검증 체계 (2026-11)
- **무사건 해의 구분.** 사례마다 `관측 범위`(obs_from·obs_to·obs_complete_domains: "이 연도 구간·분야에서는 본인의 사건을 빠짐없이 확인했다")를 선언해야 한다. 선언한 구간·분야의 기록 없는 해만 '확인된 무사건 해'로 쓰고, 그 밖의 해는 점수에서 **제외**한다(관측 누락일 수 있기 때문). 관측 범위가 없으면 해당 사례·분야는 평가하지 않으며, 모든 사례가 그렇다면 판정은 "미평가"다.
- **합성/실제 분리.** `kind` 는 real/synthetic. 합성 사례는 도구 점검용이라 기본 보고서에서 제외하고(`--include-synthetic` 로만 포함), 상태 명령의 "실제 사례 검증"에 집계하지 않는다.
- **중복 검출.** 출생 정보 지문(암호화 파일 안에만 저장)이 같으면 중복으로 거부한다(쌍둥이 등은 `allow_duplicate` 로 명시). 같은 사건의 이중 기록도 거부한다. 동의 철회(`remove`)로 지문까지 삭제된다.
- **사건 기록 품질 요약.** 상태 명령이 출처 신뢰도 분포, 월 누락 비율, 입춘 경계(점수 제외) 사건 수, 분석 구간 밖·관측 범위 밖 사건 수를 개인정보 없이 보여 준다. 출처가 낮은 사건은 1차 분석에서 제외된다.
- **결과 표현.** 미평가 / 표본 부족 / 예비 단서(재현 필요) / 구별 능력 미확인 중 하나만 쓰며 "정확도"·"적중률"은 쓰지 않는다. 보고서에는 "개발 사례의 결과는 최종 검증 성능이 아니다"를 명시하고 dev/validation을 분리해 낸다.
- **인구 통계 비교.** `--baseline`(분야별 연간 사건 비율 JSON)을 주면 정밀도의 기준율 대비 배수를 계산한다. 없으면 표본 내부의 기준율과 순열 검정만 보고한다.
- **CSV 열.** `kind, obs_from, obs_to, obs_complete_domains` 가 추가되었다(`template` 명령이 양식을 만든다).
