## 2. 새 정보 구조 (결과 화면 = 5개 영역)
```
[A 컨트롤 바]  기간 1년|5년|10년 · ◀ 2027–2031 ▶ · 입력 수정
[B 핵심 결론]  이 사주에서 중요하게 읽히는 것 (2~3줄)
               ├ 이 사주의 특징 | 선택한 시기의 변화 | 참고할 관점   (각 1~2줄)
               └ ▸ 왜 그렇게 읽나요? ▸ 판단이 달라질 수 있는 조건   (접힘)
[C 내 사주 | 시기별 흐름]  (데스크톱 2열 36% | 64%, 모바일 1열)
   내 사주의 모습                    시기별 흐름
   ├ 자연물 비유 제목 + 한 줄          ├ 타임라인(연도 노드, 클릭 선택, 입춘/대운 구간 막대)
   ├ 오행 막대(5)                      ├ 분야×연도 표(셀 클릭 → 해당 연도·분야 선택)
   ├ 계절 균형 한 줄                   └ 선택한 해 패널(한 줄·구간·그해의 주제·준비)
   ├ 핵심 특징 3(일하는 방식·돈·관계)
   └ ▸ 큰 흐름 표 / 근거 자리 (접힘)
[D 분야별 해석]  탭: 종합 | 재물 | 직업 | … → 선택한 (분야×연도)의
               한 줄 결론 · 쉬운 설명(2~4문장) · 현실에서 생각해 볼 점 · 이 해의 변화 · ▸ 왜 그렇게 해석하나요?
[E 후속 상담]  현재 보고 있는 것(연도·분야) 표시 · 추천 질문 · 질문 입력 · 기록(문서형)
[F 한계 안내]
```
읽는 순서 = A→B→C→D→E. 같은 정보는 한 곳에만: 결론(B)은 특징·변화·관점 1회, 사주 모습(C-좌)은 비유·막대·핵심 특징, 시기(C-우)는 구조 상태와 구간, 분야(D)는 선택한 분야만 상세.

## 3. 컴포넌트 계층과 데이터 대응 (프런트엔드 ViewModel)
`dashboard.js` 가 기존 API 응답(`answer.verdict`)을 `buildVM(answer)` 로 한 번 재구성하고 모든 영역이 같은 VM·같은 선택 상태(`{year, domain}`)를 참조한다. 새 점수·확률을 만들지 않는다.

| UI | 데이터(기존 필드) |
|---|---|
| 기간 전환·연도 이동 | 기존 재분석 흐름(`#yprev/#ynext/#to1/#to5/#to10`)에 위임(회원: `/reports/{id}/analyze`) |
| 핵심 결론 | `profile.conclusion`, `profile.reality`, `profile.why`, `profile.conditions` |
| 특징/변화/관점 3칸 | 결론 문장의 파생이 아니라 기존 필드 선택: 특징=`sipsung.summary`, 변화=`period.summary`(여러 해) 또는 `reality`의 시기 문장, 관점=`reality`의 분야 문장(방향/유보/충돌) |
| 자연물 비유·오행·계절 | `profile.story`(image, shape, beats, timeline) — 설명용, 판정과 무관 |
| 핵심 특징 3 | `profile.sipsung.sections`(일하는 방식·돈·관계) 첫 문장 + 더 보기 |
| 타임라인 노드 | `period.years[i]`(tone, line, standout) / 한 해: 종합 블록 |
| 구간 막대 | `verdict.segments[year]`(엔진 구간 그대로: from, to, share, 입춘/큰 흐름 교체 note) |
| 분야×연도 표 | `detail[year].blocks[].tone/tone_label` (한 해: `blocks`) |
| 선택한 해 패널 | `period.years[i].change/caution/why` + `sipsung.years[i]`(그해의 주제·준비) |
| 분야 상세 | `detail[year].blocks[domain]`: headline / story / think / counter / why |
| 후속 상담 맥락 | 선택 상태 → 추천 질문 문구, 질문 요청의 `focus_year/focus_domain`(선택 필드, 판정 무관) |

## 4. 사용자 이동 흐름
입력 → 분석 → (B 결론 읽기) → 시기별 흐름에서 해 선택 또는 표 셀 클릭 → (D) 분야 탭 전환 → "왜 그렇게" 펼침 → 후속 질문(선택한 연도·분야가 맥락) → 저장·재방문(연도 이동은 저장된 명식으로) → 삭제·로그아웃.
선택(연도·분야)은 한 곳에서 관리하며 타임라인·표·해 패널·분야 탭·상세·후속 질문 문구가 항상 같은 값을 보여 준다.

## 5. 반응형
| 폭 | 레이아웃 |
|---|---|
| ≥1440 (주 기준) | 콘텐츠 폭 최대 1480px. B 전체 폭(특징·변화·관점 3열) → C 2열(36/64) → D 탭+상세 2열(상세·보조 정보) |
| 1024~1439 | C 2열 유지(40/60), 표는 셀 축약(기호+짧은 글자), 필요시 D 1열 |
| 768~1023 | 1열. 타임라인은 가로 스크롤 안전 영역, 표는 가로 스크롤 |
| 360~767 | 1열. B가 첫 화면(800px)에 들어오게 컨트롤 바·헤더 최소화. 분야는 가로 스크롤 탭, 표는 연도 가로 스크롤(분야 열 고정), 긴 텍스트 기본 접힘 |
가로 페이지 넘침 없음. 터치 영역 ≥44px.

## 6. 타이포그래피·색
제목 명조(Noto Serif KR 계열, 큰 제목만), 본문·UI 고딕(Pretendard→Noto Sans KR→맑은 고딕), 본문 16~17px, 결론 20~26px, 핵심 제목 28~36px, 보조 14~15px. 색은 기존 토큰(종이 #F7F4EE · 표면 #FCFBF8 · 먹 #1F1A17 · 보조 #5C5148 · 선 #D9D0C4 · 인장 #A6462A · 약한 인장 #F3E6DF). 상태는 색+기호+글자(▲ 기회 ▽ 주의 ◆ 맞섬 ? 근거 부족 – 변화 없음 ● 안정). 모든 내용을 카드로 감싸지 않고 구분선·여백과 한두 개의 강조 면만 쓴다.

## 7. 비범위
계산·판정 로직, 해석 규칙, 새 운세 점수·확률, 차트 라이브러리 추가, 챗봇형 대화 UI.
